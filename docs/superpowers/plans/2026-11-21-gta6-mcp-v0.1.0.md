# gta6-mcp v0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a headless stdio MCP server with four read-only GTA VI tools whose every claim carries provenance, an evidence label and spoiler limits.

**Architecture:** Pure tool handlers over an injected HTTP client and a reviewed manifest. One module owns the network policy; one owns spoiler decisions; filtering runs last on every call.

**Tech Stack:** TypeScript 7.0.2, Node >=20, zod 4.6.7 (`zod/v4`), `@modelcontextprotocol/server@2.4.0`, `@modelcontextprotocol/client@2.4.0` (dev), Vitest 4.1.12.

**Spec:** `SPEC.md`, design in `docs/superpowers/specs/2026-11-21-gta6-mcp-design.md`.

## Global Constraints

- Exact dependency pins and a committed lockfile.
- `engines.node` is `>=20`.
- The only network hosts are `gta.fandom.com` and `en.wikipedia.org`, plus exact URLs from approved manifest entries.
- User-Agent is `gta6-mcp/0.1 (+https://github.com/ahump20/gta6-mcp)`.
- stdout carries protocol messages only.
- A failing test exists and is seen failing before each behaviour is written.
- Nothing invented: no cheat, input, source, review or test output.

## Review Focus

- A wiki row whose code cell has a malformed token must come back `unknown`, never a guessed sequence. (Task 3)
- A request that is redirected to another host must be refused, not followed. (Task 2)
- A restricted call made right after a `full` call on a warm cache must still withhold. (Task 6)
- A provider that answers HTTP 200 with an HTML challenge must count as unavailable. (Task 2)
- A page edited after review must lose its restricted disclosure until re-reviewed. (Task 5)
